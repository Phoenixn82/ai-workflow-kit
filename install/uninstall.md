# Uninstalling a profile

How to take a profile back off a machine: stop its services and timers, remove the links and files the
installer put down, undo the merged rules, and put your own files back from the backups it made.

The installer never deletes anything, so undoing it is done by hand, with the commands below. Nothing on this
page deletes your data unless the line says so (look for "deletes"). Run the commands from the clone's root, the
same folder the installer ran in, and keep the clone until the last step: most of what the installer made are
links into it.

## Before you start

1. Stop every kit job at once while you work: `touch ~/AI_Projects/_system/automations/HALT`.
2. See what the installer replaced: every file it changed has a `<file>.bak-<timestamp>` copy beside it
   ([Restoring backups](#restoring-backups)).
3. Look before you remove: `readlink -f <path>` shows where a link points. The commands below remove a link only
   while it still points into this clone, and a copied file or unit only while it is still identical to the kit's
   (`cmp`). Where the installer found something of yours already in place, it kept it, and these commands leave
   it alone.

Work in this order, top to bottom of a profile's section:

1. automations (timers), then services
2. rules (`~/.claude/settings.json`, `CLAUDE.md`, `AGENTS.md`, Codex hooks), only if you installed with `--harness`
3. kit tools, then the server setup (loki, heimdall, thor)
4. third-party tools you no longer want
5. [the clone and what is left](#last-the-clone-and-what-is-left)

```bash
touch ~/AI_Projects/_system/automations/HALT                     # pause every kit job first
systemctl --user list-timers --all | grep -E 'vault-rag|weekly|retain|lane-intel|x-scroll|fleet|probe'
find ~ -maxdepth 4 -name '*.bak-*' 2>/dev/null                   # backups the installer made
```

## Restoring backups

Before it replaces or merges a file or folder (agent settings, instruction files, anything a `--harness` step
writes), the installer moves or copies it to `<file>.bak-<timestamp>` in the same folder. One exception: an entry of
a `skills` folder is backed up to `skills.bak-<timestamp>/<name>` next to that folder (a copy inside `skills/`
would load as a second skill). The timestamp is `YYYYMMDD-HHMMSS`, so the names sort by age. Several runs leave
several backups; the **oldest** one is yours from before the kit first touched it.

```bash
f=~/.claude/settings.json                              # the file or folder to put back
old=$(ls -1d "$f".bak-* 2>/dev/null | sort | head -1)  # oldest backup = yours from before the kit
echo "$old"                                            # look first; empty = no backup (see below)
[ -n "$old" ] && mv "$f" "$f.kit-removed" && mv "$old" "$f"   # the kit's version stays beside it, just in case
# a skill: old=$(ls -1d ~/.claude/skills.bak-*/<name> | sort | head -1), then rm the kit's link and mv "$old" back
find ~ -maxdepth 4 -name '*.bak-*' 2>/dev/null         # every backup left; delete them once you are happy
```

Move the kit's version aside (or delete it) before moving the backup back: `mv` of a backup folder onto a folder
that still exists would put it inside that folder instead of replacing it.

A file with no backup did not exist before the kit (or the installer kept your copy and skipped it): removing the
kit's copy is enough.

## Server lanes

The loki, heimdall and thor profiles run `servers/linux/setup.sh` (Debian/Ubuntu) or `servers/macos/setup.sh`
with lane `media` (loki), `heimdall` or `workhorse` (thor). Those scripts change system settings, so undo them
at the keyboard or with a second SSH session open: the SSH and firewall steps can lock you out of a headless box.
Every Linux step below runs as root (`sudo -i` first). A step you skip simply leaves that hardening in place.

### Linux, every lane (base)

1. Firewall: if new rules are still on trial (`/etc/homeserver/fw-rollback` exists), first
   `install -d -m 700 /run/homeserver-fw && flock /run/homeserver-fw/lock sh -c 'systemctl stop homeserver-fw-rollback.timer homeserver-fw-rollback.service;
   nft -f /etc/homeserver/fw-rollback/active.nft'` (the table from before the trial; the lock keeps a rollback
   firing at that moment from racing it). Then `systemctl disable --now homeserver-firewall.service` (its stop removes the
   `inet homeserver` nft table) and `rm -rf /etc/homeserver/firewall.nft /etc/homeserver/fw-rollback
   /etc/homeserver/firewall.rolled-back /etc/systemd/system/homeserver-firewall.service`.
2. SSH: `rm /etc/ssh/sshd_config.d/10-homeserver.conf && sshd -t && systemctl reload-or-restart ssh` (Ubuntu with
   socket activation: `systemctl daemon-reload && systemctl restart ssh.socket`). Password logins come back to
   your distribution's default and port 2222 closes; anything that pushed backups over 2222 stops working.
3. Sleep and lid: `rm /etc/systemd/logind.conf.d/10-server.conf`, then
   `systemctl unmask sleep.target suspend.target hibernate.target hybrid-sleep.target` and
   `systemctl kill -s HUP systemd-logind`. Lid backlight: `rm /usr/local/sbin/lid-backlight /etc/acpi/events/lid-backlight
   /etc/systemd/system/acpid.service.d/lid-backlight.conf && systemctl daemon-reload && systemctl restart acpid`.
4. Logs and updates: `rm /etc/systemd/journald.conf.d/10-size.conf && systemctl restart systemd-journald`.
   `/etc/apt/apt.conf.d/20auto-upgrades` makes security updates install themselves: keep it unless you want them
   off.
5. Network units: `systemctl disable --now 'wifi-powersave-off@*' 'wol@*'`, then
   `rm /etc/systemd/system/wifi-powersave-off@.service /etc/systemd/system/wol@.service`.
6. Heat watch and alerts: `systemctl disable --now host-heat.timer`, then
   `rm /etc/systemd/system/host-heat.service /etc/systemd/system/host-heat.timer /etc/systemd/system/alert@.service
   /usr/local/bin/host-heat /usr/local/bin/alert /etc/modules-load.d/host-heat.conf /etc/host-heat/env /etc/homeserver/alert.conf`
   (the last one holds your alert topic or Telegram details). Files setup.sh or the framework's host-heat
   installer replaced are kept beside them as `<file>.bak-<time>`
   (`ls /usr/local/bin/host-heat.bak-* /etc/host-heat/env.bak-* /etc/systemd/system/host-heat.*.bak-*`): move back
   what you want, delete the rest.
7. Tailscale: `tailscale logout`, remove the machine in the Tailscale admin console, then remove the package
   ([tailscale](#tailscale)). setup.sh added Tailscale's apt repository: `rm /etc/apt/sources.list.d/tailscale.list`;
   its key goes with `apt-get remove tailscale-archive-keyring` (or `rm /usr/share/keyrings/tailscale-archive-keyring.gpg`).
8. `systemctl daemon-reload`. The base packages (`openssh-server`, `avahi-daemon`, `nftables`, `acpid`,
   `unattended-upgrades` and friends) stay; remove them with `apt-get remove` only if nothing else needs them.

3. Data: `/opt/homeserver/media` holds the Jellyfin library database and settings (`rm -r` deletes them);
   `/srv/media` holds **your media files**. Neither is removed for you.
4. Backups (thor pulls them): the nightly database snapshot: `systemctl disable --now db-snapshot.timer`, then
   `rm /etc/systemd/system/db-snapshot.service /etc/systemd/system/db-snapshot.timer
   /etc/systemd/system/db-snapshot.service.d/10-user.conf /usr/local/bin/db-snapshot`. The read-only account thor
   logs in as: its read access first, `setfacl -R -x u:backup-pull /opt/homeserver/media` and
   `find /opt/homeserver/media -type d -exec setfacl -x d:u:backup-pull {} +`, then `userdel -r backup-pull` (removes
   `/var/lib/backup-pull` with thor's key).

### Linux, lane heimdall

  once you no longer use Docker without sudo.
- Lingering lets user timers run while nobody is logged in. Turn it off with `loginctl disable-linger "$USER"`
  only when no user service you still want needs it (FreeLLMAPI does).
- `~/.config/ai-workflow-kit/hosts.env` and `~/AI_Projects/_system/second-brain` are your configuration and your
  notes: keep them, or delete them yourself.
