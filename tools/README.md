# tools/ — how this repo stays in sync (maintainer only)

You can ignore this folder unless you maintain your own copy of the kit.

- **Hermes export:** `framework/_tools/hermes-kit/`, `helper-wall/` and `thor-wake-proxy/` ship the optional [multi-model harness](../docs/hermes.md). Its installer self-test uses a temporary HOME; helper and proxy tests are offline. Wiring checks use manifest entrypoints for installed copies and recognize declared third-party commands.
- **`sync-kit.py`** — rebuilds `framework/` from the live workspace. The source list in `sources()` is an explicit allowlist; nothing else is exported. It stages into a temp dir, scrubs, refuses binary files, runs gitleaks (fails closed if gitleaks is missing), and only with `--apply` replaces `framework/`.
- **`scrub.py`** — rewrites home paths to `$HOME`, applies the replacement rules to file contents **and file names**, then blocks on: leftover username, real-looking credentials, forbidden private paths (vault content, `.env`, secret stores), or any verify-denylist match.
- **`scrub.py --check <paths...>`** — the same rules, never writes: lists (file:line, rule number) everything the scrub would rewrite plus every guard hit, and treats binary files as hits. Exit 0 clean, 1 hits, 2 config error. It refuses to run on the template rules alone (`--template-ok` to override). `--guard-denylist <file> --owner-repo <owner/repo>` adds the public push gate's personal-data denylist (through `framework/_system/skills/guard/scripts/public_push_gate.py`, or `$GUARD_GATE_DIR`). Matched text is printed only with `--show`. It also scans a copy of each file with literal `\n`, `\t` and `\r` escapes blanked, because a `\b` rule cannot see a word right after one inside a string literal (`"...\nName"`) and the scrub misses it there.
- **`githooks/`** — enable once per clone with `git config core.hooksPath tools/githooks`. `pre-commit` blocks a commit when the author or committer email is not a GitHub noreply address, when a private rules or denylist file is staged, when `scrub.py --check` finds anything in the staged blobs (the index, not the working tree), or when gitleaks finds a secret (gitleaks missing = blocked). Point it at your guard denylist with `git config kit.guardDenylist <path>`. `commit-msg` runs the same check on the message. `pre-push` rescans every commit the remote does not have yet with `check-commits.sh`, then chains to the pre-push in your global `core.hooksPath`, so a global push gate keeps running. Never commit or push with `--no-verify`; fix the content.
- **`check-commits.sh <rev-list args>`** — rescans commits with the current rules: author and committer emails (noreply only), messages, every file each commit adds or changes (`scrub.py --check`, plus the guard denylist when configured) and gitleaks over the same range. Run it before a push, e.g. `tools/check-commits.sh origin/main..HEAD`: the rules can grow after a commit was made. Fix a hit in a commit that is not on the remote yet by rewriting that commit, never with a follow-up commit (the old blob would still ship).
- **`sync-kit.py` export assertions** — during staging, entries and instruction text that name an excluded tool are stripped (dispatcher table rows, comment lines, Markdown sections whose heading matches, bullets, table rows, parentheticals); afterwards the run fails if any excluded tool name survives anywhere in the export, or if an exported executable, unit or settings file references a first-party executable, unit or slice that is not exported. Personal names for both live in the private rules: `excludedTools` and `dropSectionTerms`.
- **`test_privacy_tooling.py`** — runnable check for all of the above with fake rules: `python3 tools/test_privacy_tooling.py`.
- **`run-selftests.sh`** — runs bundled tools in a temporary HOME with installed-file fixtures and a private runtime directory. Reports `PASS`, `FAIL`, or `SKIP` (exit 77 from a tool). Missing systemd user scopes and optional `sqlite-vec` skip with a reason; x-scroll still runs its offline tests when web/Claude Code are absent. `WITH_BUS=1` opts into live user-scope checks; `VAULT_RAG_PY=<a Python with sqlite-vec>` (e.g. vault-rag's `.venv/bin/python`) runs the vault-rag tests instead of skipping them. `python3 tools/test_selftests.py` checks the reporting and fixtures.
- **`test_telegram_setup.py`** — replays the documented `tg-admin` setup block of `profiles/telegram/README.md` verbatim in a fresh HOME against a fake Telegram (`telegram-fakes/sitecustomize.py`; no network where `unshare -c -n` works) and passes only when the sender token is placed, the owner is claimed, every topic is mapped and `tg --test fleet` is routed silently: `python3 tools/test_telegram_setup.py` (about 20 s).
- **`scrub-rules.json`** — a template with fake entries. Real rules live in a git-ignored `scrub-rules.local.json` (or any path in `$SCRUB_RULES`). Never commit real rules.

```bash
SCRUB_RULES=~/private/scrub-rules.local.json python3 tools/sync-kit.py           # dry run
SCRUB_RULES=~/private/scrub-rules.local.json python3 tools/sync-kit.py --apply   # replace framework/
python3 tools/scrub.py some/dir                                                  # scrub any folder (rewrites)
git ls-files -z | xargs -0 python3 tools/scrub.py --check                        # verify, never writes
tools/check-commits.sh origin/main..HEAD                                         # rescan new commits
```

Hand-written parts (`README.md`, `docs/`, `servers/`, `examples/`) are not touched by the sync.
